# Дизайн-система «Худеем на здоровье»

Источники: Figma «ЗОЖ приложение (2026)», файл `KZWzsMm3PXxyLlRxq9Qv8Q` (только чтение);
Storybook https://storybook.thinkingoutloud.ru (basic auth у владельца). Снято 2026-11-09.
Перенос каталога в Storybook не означает готовую production-систему: сверка с Figma — выборочная.

Как вести файл (из `pirschuk/BAR`):
- Правило — проверяемое значение («радиус карточки 20»), а не вкус.
- Источник в скобках: `[Figma: компонент ID]`, `[Mobbin: App — экран]`, «(решение владельца)».
- Противоречие новому правилу — показать конфликт и спросить, не перезаписывать молча.
- Отменённое — вычёркивать с причиной, чтобы не вернуть по ошибке.

## 1. Принципы

1. **Одно действие — один экран.** У экрана один главный акцент; добавление блюда — выбрал → добавил → вернулся. (решение владельца)
2. **Меньше шума.** Никаких подписей, счётчиков и блоков, которые не помогают действию. (решение владельца)
3. **Сначала библиотека.** Экран собирается из компонентов Figma-библиотеки; новое — только с пометкой «не из DS». (решение владельца)
4. **Не выдумывать данные.** Нормы, лимиты и правила, которых нет в ТЗ/Figma, не вводить молча. (решение владельца)
5. **Смело, но удобно.** Приложение не должно быть сухим и дефолтным; креатив допустим, если не добавляет шагов и шума. (решение владельца)

## 2. Сетка и отступы

- Вьюпорт прототипа **393×852** (iPhone 14 Pro); края экрана **16**.

## 8. Паттерны из референсов

Формат: правило → значение → источник → файл в `refs/` → компонент DS.

- Итог приёма в шапке группы одной строкой (ккал + БЖУ), без отдельной плашки → [Mobbin: MacroFactor — дневник] →
  `refs/mobbin/1-diary-macrofactor-meal-groups.jpg` → строка над `[-meal widget-inner]`.
- Приём на главной — карточка: название + бейдж количества, БЖУ слева, ккал справа; вся карточка открывает
  страницу приёма → (макет владельца 2026-11-09), [Mobbin: MyFitnessPal — дневник] → `1-diary-myfitnesspal-meal-rows.jpg`.
- Страница приёма: итог сверху (ккал + БЖУ без полос), ниже блюда, «+» и повтор → [Mobbin: Yazio — Breakfast] →
  `2-meal-yazio-breakfast.jpg` → `[Meal] Widget` без цели + `meal blocks`.
- Тип приёма выбирается в шапке/на экране и предустановлен → [Mobbin: MyFitnessPal — Search Food «Breakfast ▾»] →
  `3-add-myfitnesspal-search.jpg` → элемент HAR-710 или `Chip` ×4.
- «Недавние / Избранное» вкладками над списком → [Mobbin: Yazio — Frequent/Recent/Favorites] → `3-add-yazio-search-tabs.jpg` → `SegmentedControl`.
- Фраза со вставками для выбора значений → [Mobbin: ChatGPT — sticker prompt] → `4-pattern-chatgpt-sentence-tokens.jpg` → не из DS.
- Одна карточка в фокусе, соседние выглядывают → [Mobbin: Airbnb — «2 of 4»] → `4-pattern-airbnb-card-deck.jpg` → не из DS.
- Крупные плитки быстрых действий → [Mobbin: How We Feel — Tools] → `4-pattern-howwefeel-tiles.jpg` → `[-Meal Card]`.

## 9. Решения владельца (не нарушать без явного согласия)

- Добавляем **одно блюдо**, а не весь приём: после добавления — сразу назад к приёму с тостом. (2026-11-10)
- Нет блока «Как вчера?» на экране добавления блюда. (2026-11-10)
- Камера и галерея — **одна кнопка** «Распознать по фото», галерея внутри камеры. (2026-11-10)
- Избранное — отдельная вкладка «Избранное» с поиском по нему. (2026-11-10)
- Тип приёма от времени не зависит: со страницы приёма — этот приём, иначе последний выбранный, первый раз «Завтрак». (2026-11-10)
- ~~Экран «Добавить блюдо» с чипами, поиском над подборками и плитками `[-Meal Card]`~~ — отклонено: поиск читался как поиск по своим спискам, плитки не понравились. (2026-11-10)
- Добавление блюда: сначала шторка «Что добавляем?» (со страницы приёма — пропускается), экран приёма «Обед ▾», «Найти в каталоге» → отдельный экран «Искать продукт», «Избранное / Недавние» списком `[-My food] -list`, касание → карточка блюда. (2026-11-10)
- Много избранного: на экране приёма общий поиск (каталог + избранное, без дублей, избранные первыми), строка «Избранное · N ›» → экран «Избранное» с поиском только по нему, алфавитными группами (буква прилипает) и указателем букв при > 15; «Недавние» ≤ 5. (2026-11-10)
- Не держаться за паттерны и готовые компоновки: искать красивые экраны на Mobbin (в т. ч. вне ниши) и делать красиво; токены DS сохраняем, новые элементы помечаем «не из DS». (2026-11-10)
- Камера — круглая кнопка Blue/100 56×56 рядом с полем поиска; нижняя панель способов убрана; «Ввести вручную» — строка рядом с «Избранное». Экраны добавления — на градиенте Gradient_BG3 с белыми карточками без обводки, мягкая тень. (2026-11-10)
- Рамка экранов добавления — как «Добавить активность»: градиент (в т. ч. под строкой состояния), белая квадратная «×» r12 слева, заголовок по центру, белая шторка r24 сверху. Понравились варианты 1 (поиск + камера) и 4 (бенто) → объединены в «Шторку»: тип приёма сегментами ×4 вверху шторки, поиск, бенто-входы, недавние. (2026-11-10)
- ~~Тесты «Фраза» и «Карточки»~~ — не выбраны, удалены из кода. (2026-11-10)
- Варианты для сравнения — **разные компоновки**, а не один экран с разными сценариями. (2026-11-10)
- Итог приёма пищи: не плодить одинаковые блоки, не дублировать прогресс-бары виджета «Питание», не вводить нормы
  калорий на приём (их нет в ТЗ). (2026-11-09)
- Шторка дублирования приёма: тип приёма, дата и время (по умолчанию сейчас), выбор блюд. (2026-11-09)
- ~~Варианты «Поиск-герой» и «Как в чате»~~ — отклонены: не по компонентам и неудобно. (2026-11-10)
- ~~Итог приёма: карточка с долей дневной нормы и экран с полосами~~ — отклонено (2026-11-09).

- **Рамка экранов добавления** (скриншоты «Добавить активность», «Мои блюда»): градиент до строки состояния, белая квадратная «×»/«‹» r12, заголовок по центру, белая шторка r24 — **неподвижная**: поиск закреплён сверху шторки, прокручивается только содержимое; высота шапки фиксирована. Сегментов типа приёма в шторке нет; ~~подзаголовок «на обед ▾»~~, ~~плашка над поиском~~, ~~плавающая плашка внизу~~ — отклонены («странно»). Сейчас выбираем из A — заголовок «Обед ▾», B — сегменты в карточке блюда у кнопки «Добавить», C — шторка на входе (переключатель «Где менять приём»). Список блюд — одна обведённая карточка с сердечками и «ккал · г + БЖУ»; буквенные группы — только для длинного избранного (>15). Оба варианта — «Шторка» (бенто) и «Поле + камера» (кнопка камеры справа от поиска, ссылки списком) — в этой рамке. (2026-11-10)
- **Экран «Приёмы пищи» — без отдельных экранов приёма** (в приёме редко больше 5 блюд): ~~блоки → страница приёма~~, ~~гибрид с «Ещё N» → страница~~ — отклонены. Рассматриваем только варианты на одном экране: раскрывающиеся блоки, открытые блоки с действиями в шапке, ленту дня (переключатель «Экран «Приёмы пищи»»). (2026-11-10)

## 10. Чек-лист визуальной проверки (для `/look` и `ui-inspector`)

- [ ] Ничего не выходит за ширину экрана, нет горизонтального скролла.
- [ ] Все интерактивные элементы ≥ 44×44.
- [ ] Текст не обрезан неожиданно (только намеренно, с `…` или в 2 строки).
- [ ] Вторичный текст читается; контраст основного ≥ 4.5.
- [ ] Отступы по шкале, края экрана 16.
- [ ] Один главный акцент; нет повторов и лишних подписей.
- [ ] Все элементы — из библиотеки DS или явно помечены «не из DS».
- [ ] loading / empty / error не «прыгают» по геометрии.
- [ ] Клавиатура прототипа не перекрывает поле и главное действие.
- [ ] Нет ошибок в консоли; сценарий пройден до конца (добавление → возврат → тост).
