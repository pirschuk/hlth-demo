Дополнительно: $ARGUMENTS

1. Прочитай `plan.md`. Если статус не «утверждён» и пользователь в этом сообщении явно не утвердил
   план — остановись и спроси. Прочитай `CLAUDE.md` и `.claude/skills/design-system/SKILL.md`.
2. **Компоненты.** Для каждого элемента экрана возьми компонент из «Компонентов библиотеки» скилла.
   Если стиль компонента уже есть в прототипе (`src/app.css`, модули) — переиспользуй класс.
   Нового компонента нет в библиотеке → сверь с Figma (`get_metadata` / `get_variable_defs`) и
   сделай по нему; если в библиотеке его нет вовсе — помечай «не из DS» в комментарии модуля.
3. **Код** — модулем `src/modules/<фича>.js|css`, в шапке модуля — назначение и список компонентов
   DS с ID. Подключение к бандлу — точечными правками `src/app.js`. Только токены `--swift-*` / `--figma-*`.
   Варианты для сравнения — за переключателем в панели; основной экран не ломать.
4. `npm run build`.
5. **Визуальная проверка** во всех состояниях из плана: Playwright-сценарий или
   `node scripts/screenshot.mjs` → `Read` → чек-лист скилла → правки → повтор, пока чисто и без
   ошибок консоли. Для независимого взгляда — субагент `ui-inspector`, закрыть его P0/P1.
6. Финальные скриншоты — в `docs/previews/` + строка в `docs/previews/README.md`.
7. Отметь в `plan.md` выполненные критерии, статус «сделано». Коммит и пуш.
8. Ответ: что сделано, из каких компонентов, что не из DS, пути к скриншотам, что осталось.
