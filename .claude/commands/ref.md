Референс: $ARGUMENTS

Ты — дизайнер, который превращает референс в правила дизайн-системы. Код приложения в этой
команде не пишешь.

1. **Получи изображения.**
   - Путь в `refs/` или картинка владельца → открой через `Read`.
   - Описание или ссылка Mobbin → `mcp__Mobbin__search_screens` (`platform: ios`, 3–6 результатов)
     или `mcp__Mobbin__search_flows`. Скачивать по `image_url` из контейнера нельзя: превью из ответа
     MCP лежат в `tool-results/` — лучшие скопируй в `refs/mobbin/<зона>-<app>-<экран>.jpg`
     (зоны: 1 дневник, 2 страница приёма, 3 добавление еды, 4 общие паттерны; новые — дописать в `refs/README.md`).
   - Figma (`KZWzsMm3PXxyLlRxq9Qv8Q`, только чтение) → `get_screenshot` с `enableBase64Response: true`,
     размеры — `get_metadata`, токены — `get_variable_defs`.
2. **Разбери каждый экран** (смотри на картинку, не на метаданные): сетка и поля, отступы между
   блоками, иерархия кеглей и весов, радиусы, плотность списков, тач-зоны, цвета/контраст,
   поведение (шторки, свайпы, пустые состояния, микро-взаимодействия), сколько касаний до результата.
   Значения оценивай в pt относительно ширины 393.
3. **Сверь с библиотекой DS.** Если паттерн реализуется существующим компонентом Figma — запиши
   соответствие «паттерн → компонент (ID)». Если нет — пометь «не из DS, нужен компонент».
4. **Обнови `.claude/skills/design-system/SKILL.md`:** раздел «Паттерны из референсов» в формате
   «правило → значение → [Mobbin: App — экран] → файл в refs/ → компонент DS». Не дублируй записанное;
   противоречие с правилом или решением владельца — покажи конфликт и предложи решение, молча не
   перезаписывай. Короткий разбор — в `refs/mobbin/ANALYSIS.md`.
5. **Предложи изменения** экранов или модулей (списком, без кода).

Ответ: 3–7 извлечённых правил, ссылки на экраны (`mobbin_url`), что изменилось в скилле, предложения.
