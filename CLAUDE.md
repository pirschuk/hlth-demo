# Худеем на здоровье — интерактивный прототип iOS-приложения (iOS Studio)

Веб-прототип мобильного приложения о питании и здоровье. Публикуется статикой на GitHub Pages.
Процесс адаптирован из набора правил `pirschuk/BAR` (`kit/`): план → компоненты дизайн-системы → экран →
визуальная проверка → публикация.

## Стек и устройство

- **Исходного проекта нет.** `src/app.js` и `src/app.css` — отформатированный собранный бандл (React 19, свой стор `N`,
  реестр экранов и листов). Правки старого кода — точечно в них.
- **Новое — только модулями** в `src/modules/<фича>.js|css`. Сборка вставляет `*.js` перед `render()`, `*.css` — в конец
  стилей. В модулях доступны сущности бандла: `n` (jsx), `V` (React), `N` (стор), `we()` (подписка), `Q` (иконка),
  `$` (текст с токеном шрифта), `re` (кнопка DS), `rt` (формат чисел), `sl` (дата «сегодня»).
- Экраны вкладки «Статистика» — стек `state.stacks.stats`, листы — `N.sheet(kind, data)` → `xg()` в `src/app.js`.
  Тестовые варианты и переключатели — в панели «Управление приложением → Поведение» (`state.controls.*`).
- Вьюпорт телефона в прототипе — **393×852** (iPhone 14 Pro), масштаб 0.9. Интерфейс — на русском.

## Команды

- `npm install` — один раз (esbuild).
- `npm run build` — сборка `assets/index-<hash>.{js,css}` и обновление `index.html`. **Обязательна перед коммитом.**
- `python3 -m http.server 8765` — локальный сервер, http://localhost:8765.
- `node scripts/screenshot.mjs "<экран>" [имя] [--set "<панель>=<значение>"] [--click "<локатор>"] [--scroll N]` —
  скриншот телефона @2x в `.screenshots/`; экран — пункт списка «Экран» в панели («Питание», «Добавить еду»…).
  Печатает ошибки консоли.
- `python3 scripts/montage.py out.png a.png b.png …` — склеить скриншоты в ряд.

- **Storybook:** https://storybook.thinkingoutloud.ru (basic auth у владельца, в репозиторий не кладём).
- **Скилл `design-system`** — токены, компоненты с ID в Figma, паттерны, решения владельца.
- **Mobbin** — через MCP (`search_screens` / `search_flows`), превью — в `refs/mobbin/`.

## Процесс (обязателен)

1. `/idea <фича>` — только продуктовое мышление и референсы, код не пишем. Результат — `plan.md`. Ждём «го».
2. `/code` — реализовать утверждённый `plan.md`: компоненты берём из библиотеки DS (Figma), экран собираем из них.
3. `/look <экран>` — скриншот, разбор глазами, исправление огрехов.
4. `/ref <ссылка|описание|файл>` — референс → правила в скилл `design-system`.
5. Готово → коммит и пуш в рабочую ветку `claude/**` → владелец смотрит → решение.

Субагент: `ui-inspector` (визуальная критика по скриншотам).

## Правила

- **Сначала референсы и библиотека, потом код.** Перед новым экраном — Mobbin (3–6 экранов, можно вне ниши) и поиск
  подходящего компонента в Figma-библиотеке (список ID — в скилле). Не придумывать элемент, если он есть в библиотеке.
- **Только компоненты и токены DS.** Цвета, радиусы, отступы, шрифты — переменные `--swift-*` / `--figma-*`.
  Чего нет в библиотеке — явно помечать «не из DS» в ответе и в коде модуля.
- **Не выдумывать данные и нормы.** Цифры, лимиты и правила, которых нет в ТЗ/Figma (например, нормы на приём пищи), не
  вводить молча — спросить или явно пометить как допущение.
- **Тестовые варианты — за переключателем** в панели, основной экран не ломать. Отвергнутые варианты удалять из кода.
- **Визуальная проверка обязательна:** сборка → сервер → `scripts/screenshot.mjs` или Playwright-сценарий → открыть
  `.png` через `Read` → чек-лист из скилла → исправить → повторить. Сценарии проверять с нулевыми ошибками консоли.
  Показывать результат только после чистого скриншота.
- **Скриншоты:** черновые — в `.screenshots/` (не коммитим). Финальные этапа — в `docs/previews/`
  `<этап>-<экран>[-<состояние>].png` + строка в `docs/previews/README.md`.
- **Решения владельца** записываются туда, где их прочтут в следующий раз: визуальные — в скилл `design-system`
  (раздел «Решения владельца»), продуктовые — в «Решения» `plan.md`, процессные — сюда.
- Коммит и пуш — в конце хода, рабочее дерево чистое. Секреты (пароли Storybook и т. п.) в репозиторий не класть.
- Прототип публичен на GitHub Pages: не класть туда то, что нельзя показывать.
